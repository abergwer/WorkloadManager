# WorkloadManager Data Model Documentation

## Overview

The WorkloadManager system uses a comprehensive data model designed to support job execution tracking, retry logic, progress monitoring, and detailed logging.

---

## Job Model

The `Job` class represents a unit of work in the system.

### Properties

#### Core Identification
- **Id** (int)
  - Unique identifier for the job
  - Auto-generated by the database

- **Type** (string)
  - Type of job to execute (e.g., "email", "webhook", "report", "batch")
  - Required field

- **Name** (string)
  - Human-readable name for the job
  - Required field

- **Description** (string, optional)
  - Detailed description of what the job does

#### Status & Execution
- **Status** (JobStatus enum)
  - Current state of the job
  - Values:
    - `Scheduled` - Waiting for scheduled execution time
    - `Pending` - Ready to execute
    - `Processing` - Currently executing
    - `Completed` - Successfully completed
    - `Failed` - Execution failed
    - `Cancelled` - Job was cancelled

#### Payload & Results
- **Payload** (string, JSON)
  - Input data for job execution
  - Serialized as JSON string
  - Example: `{"recipient": "user@example.com", "subject": "Hello"}`

- **Result** (string, JSON)
  - Output/result from job execution
  - Serialized as JSON string
  - Populated after job completion

#### Priority & Attempt Management
- **Priority** (int, 0-10)
  - Job priority level
  - 0 = Lowest, 10 = Highest
  - Default: 5
  - Used for job queue ordering

- **CurrentAttempt** (int)
  - Current attempt number (0-indexed)
  - Incremented on each retry
  - Default: 0

- **MaxAttempts** (int)
  - Maximum number of retry attempts allowed
  - Minimum: 1
  - Default: 3
  - Example: MaxAttempts=3 means up to 3 attempts total

#### Error Handling
- **ErrorMessage** (string, optional)
  - Human-readable error message from last failed attempt
  - Populated when job fails

- **ErrorDetails** (string, optional)
  - Detailed error information or stack trace
  - Populated when job fails

#### Progress Tracking
- **ProgressPercentage** (int, 0-100)
  - Progress indicator for long-running jobs
  - Updated during execution for batch jobs
  - Default: 0

#### Scheduling
- **ScheduledFor** (DateTime?, optional)
  - When the job should execute
  - If null, executes immediately
  - If future date, job status set to `Scheduled`

#### Timestamps
- **CreatedAt** (DateTime)
  - When the job record was created
  - Set automatically on creation
  - UTC timezone

- **StartedAt** (DateTime?, optional)
  - When job execution started
  - Set to null initially
  - Updated when job enters `Processing` state

- **CompletedAt** (DateTime?, optional)
  - When job execution completed
  - Set to null initially
  - Updated when job exits `Processing` state

- **UpdatedAt** (DateTime)
  - Last update timestamp
  - Updated frequently during execution
  - UTC timezone

#### Idempotency & Duplicate Prevention
- **IdempotencyKey** (string, optional)
  - Unique key for preventing duplicate job processing
  - Format: GUID or custom key
  - Example: `order-123-retry-1`
  - Application should check this before processing duplicate jobs

#### Navigation Properties
- **Logs** (ICollection<JobLog>)
  - Collection of log entries associated with this job
  - For detailed execution tracking and debugging

## JobLog Model

The `JobLog` class captures execution logs and events for a job.

### Properties

- **Id** (int)
  - Unique identifier for the log entry

- **JobId** (int)
  - Foreign key referencing the Job
  - Establishes one-to-many relationship

- **Level** (LogLevel enum)
  - Log severity level
  - Values: `Info`, `Warning`, `Error`

- **Message** (string)
  - Log message
  - Required, human-readable text

- **Metadata** (string, JSON)
  - Additional contextual data as JSON
  - Example: `{"duration": 1234, "itemsProcessed": 50}`
  - Optional

- **Timestamp** (DateTime)
  - When the log entry was created
  - UTC timezone

- **Job** (Job, navigation property)
  - Reference to the associated Job (optional)

## Supporting Enums

### JobStatus

```csharp
public enum JobStatus
{
    Scheduled = 0,    // Awaiting scheduled execution time
    Pending = 1,      // Ready to execute
    Processing = 2,   // Currently executing
    Completed = 3,    // Successfully completed
    Failed = 4,       // Execution failed
    Cancelled = 5     // Job was cancelled
}
```

### LogLevel

```csharp
public enum LogLevel
{
    Info = 0,      // Informational message
    Warning = 1,   // Warning - something unexpected
    Error = 2      // Error - job execution failed
}
```

## Supporting DTOs

### JobCreateRequest

Used for creating jobs via API endpoints.

```csharp
public class JobCreateRequest
{
    public string Type { get; set; }                    // Required
    public string Name { get; set; }                    // Required
    public string Description { get; set; }             // Optional
    public string Payload { get; set; }                 // Optional, JSON
    public int Priority { get; set; } = 5;              // 0-10, default 5
    public int MaxAttempts { get; set; } = 3;           // Default 3
    public DateTime? ScheduledFor { get; set; }         // Optional
    public string IdempotencyKey { get; set; }          // Optional
}
```

### JobResult

Returned after job execution.

```csharp
public class JobResult
{
    public bool Success { get; set; }                   // Execution success
    public string Message { get; set; }                 // Status message
    public object Data { get; set; }                    // Result data
    public Dictionary<string, object> Metadata { get; set; } // Additional info
}
```

## Usage Examples

### Creating a Job with JobBuilder

```csharp
var job = new JobBuilder("email", "Send Welcome Email")
    .WithDescription("Send welcome email to new user")
    .WithPayload(JsonSerializer.Serialize(new { email = "user@example.com" }))
    .WithPriority(8)
    .WithMaxAttempts(5)
    .WithScheduledTime(DateTime.UtcNow.AddHours(1))
    .WithIdempotencyKey("user-123-welcome-email")
    .Build();
```

### Creating a Job Directly

```csharp
var job = new Job
{
    Type = "webhook",
    Name = "Send to Webhook",
    Priority = 7,
    MaxAttempts = 3,
    IdempotencyKey = Guid.NewGuid().ToString(),
    CreatedAt = DateTime.UtcNow,
    UpdatedAt = DateTime.UtcNow,
    Status = JobStatus.Pending
};
```

### Logging Job Events

```csharp
JobLogger.LogInfo(job, "Job started", new Dictionary<string, object>
{
    { "InitialPayload", "..." }
});

JobLogger.LogError(job, "Job failed", exception, new Dictionary<string, object>
{
    { "Attempt", 2 },
    { "Retryable", true }
});
```

### Accessing Job Information

```csharp
// Check if job can be retried
if (job.Status == JobStatus.Failed && job.CurrentAttempt < job.MaxAttempts)
{
    // Perform retry
}

// Get execution duration
var duration = job.CompletedAt.HasValue 
    ? (job.CompletedAt.Value - job.StartedAt.Value).TotalSeconds 
    : 0;

// Access logs
foreach (var log in job.Logs)
{
    Console.WriteLine($"[{log.Level}] {log.Message}");
}
```

## Database Considerations

### Indexes (recommended)

- **Job.Status** - For querying jobs by status
- **Job.Type** - For filtering by job type
- **Job.CreatedAt** - For time-based queries
- **Job.IdempotencyKey** - For duplicate prevention (unique index recommended)
- **JobLog.JobId** - For retrieving logs by job
- **JobLog.Timestamp** - For time-based log queries

### Data Types

- Status enums stored as integers (0-5)
- JSON payloads/results stored as TEXT/NVARCHAR MAX
- DateTime fields use UTC timezone
- Metadata in JobLog stored as JSON string (can be parsed back to objects)

## Workflow Examples

### Standard Job Execution

1. Job created with `Status = Pending`
2. Job picked up for execution, `Status = Processing`, `StartedAt` set
3. Job completes:
   - Success: `Status = Completed`, `Result` populated, `CompletedAt` set
   - Failure: `Status = Failed`, `ErrorMessage` set, `CompletedAt` set

### Retry Workflow

1. Job execution fails, `Status = Failed`, `ErrorMessage` set
2. Application checks: `CurrentAttempt < MaxAttempts`
3. If true: Reset `Status = Pending`, increment `CurrentAttempt`, reschedule
4. If false: `Status = Failed`, no more retries

### Scheduled Job Workflow

1. Job created with `ScheduledFor = future_time`, `Status = Scheduled`
2. Scheduler monitoring `Status = Scheduled` and `ScheduledFor <= now`
3. Status changed to `Pending`, then execution proceeds as normal

### Idempotency Workflow

1. Client sends job with `IdempotencyKey = "unique-key-123"`
2. Before processing, app checks if job with this key exists
3. If exists: Return existing job result (prevent duplicate)
4. If new: Create and process job

## Best Practices

1. **Always set CreatedAt and UpdatedAt** - Use UTC timezone
2. **Use IdempotencyKey for critical operations** - Prevents duplicate processing
3. **Log all significant events** - Helps with debugging and monitoring
4. **Set appropriate MaxAttempts** - Balance reliability with resource usage
5. **Use Priority for important jobs** - Help scheduler prioritize work
6. **Validate Payload as JSON** - Ensure data integrity
7. **Handle long-running jobs** - Update ProgressPercentage for UX feedback
8. **Archive old logs** - Prevent database bloat over time
